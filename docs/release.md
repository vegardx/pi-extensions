# Releases

This repo uses [semantic-release](https://semantic-release.gitbook.io/) to cut
tagged releases automatically. Distribution is `git clone` + `pi -e
./packages/<name>` — nothing is published to npm.

## How it works

```
PR merged to main
  → CI runs `npm run check`
  → if green, the `release` job runs `npx semantic-release`
  → semantic-release scans conventional commits since the last tag
  → if any release-worthy commits exist:
      - bumps the version
      - creates the git tag (e.g. `v0.2.0`)
      - creates the GitHub Release with autogenerated notes
      - comments on closed issues + merged PRs with the version
  → if not, no release is cut
```

Red CI on main → no release. The `release` job has `needs: check`.

## Bump rules

| Commit type | Bump |
|---|---|
| `feat:` | minor |
| `fix:` | patch |
| `perf:` | patch |
| `BREAKING CHANGE:` footer or `!` after type (e.g. `feat!:`) | major |
| `chore`, `docs`, `test`, `style`, `ci`, `build`, `refactor` | no release |

`refactor:` deliberately does not trigger a release. If a refactor is
user-visible, mark it `feat:` or add a `BREAKING CHANGE:` footer.

## Pre-1.0 quirk

The first `BREAKING CHANGE:` after `v0.1.0` will jump straight to `v1.0.0` —
that's semantic-release's default. If you want to stay in `0.x` longer, hold
breakers until the project is ready to commit to a `1.0` API.

## Skipping a release

Append `[skip ci]` to the commit message — the workflow won't run.

## Forcing a major bump

Add a `BREAKING CHANGE: <description>` footer to the commit body, or use the
`type!:` syntax (`feat!:`, `fix!:`).

## Rollback

All releases are tagged in git. To pin to a known-good version:

```bash
git checkout v0.1.0
```

To roll the project back, revert the offending commits on `main` and let the
next merge cut a fresh release. Don't delete published tags.

## Configuration

- `.releaserc.json` — semantic-release plugins (commit-analyzer,
  release-notes-generator, github).
- `.github/workflows/ci.yml` — `release` job (`needs: check`,
  `if: github.ref == 'refs/heads/main' && github.event_name == 'push'`).

We deliberately do **not** use `@semantic-release/npm` (packages are private)
or `@semantic-release/git` (we don't commit a `CHANGELOG.md` back to main —
release notes live on GitHub Releases).
